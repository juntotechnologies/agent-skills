# PR 4: Portable Project Links

Status: underway

Branch: `bugfix/portable-project-links`

## Goal

Make project symlinks generated by the canonical installer portable across
machines and checkouts by storing paths relative to each project target.

## Context

PR 2 introduced project installation but used absolute sources for
`AGENTS.md` and `.agents/skills/*`. Those links work locally but cannot be
committed to a project repository and restored on a machine with a different
home path. Chem-inventory PR 171 requires portable links.

## Implementation Checklist

### Tier 1 - Link contract

- [ ] Change installer tests first to require relative project link targets.
- [ ] Add focused tests for relative-path calculation across sibling and nested
      directories.

### Tier 2 - Installer

- [ ] Generate project instruction and `.agents` skill targets relative to
      their link directories.
- [ ] Preserve existing global-link behavior, atomic project installation, and
      idempotence.
- [ ] Update installation documentation.

## Smoke Tests

- [ ] Run the installer twice against a temporary workspace and confirm all
      project links remain valid and unchanged.
- [ ] Run it against chem-inventory after PR 171's links exist and confirm the
      project reports already linked.

## Product Decisions

- Global user-level links remain absolute because they are machine-local and
  are never committed to a repository.
- Project links are always relative because they are version-controlled.

## Scope

- Project-link path generation, tests, and documentation.

## Non-Goals

- Changing project discovery or canonical content.
- Modifying chem-inventory application code.
